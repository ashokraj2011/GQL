01 · The unit

Skills — how the model plugs in

A skill is the only doorway between conversation and kernel: a folder with a SKILL.md body, a registry entry that assigns its behavioral contract, and a CLI command it wraps. This guide covers the anatomy, the invocation loop, and how /sflow-* chains work into a governed flow.

plugin/skills/
├── registry.yml                  # every skill · its contract class · stamped policies
└── sflow-status/
    └── SKILL.md                  # frontmatter + body the model reads on invocation

SKILL.md holds frontmatter (name, description, the command it wraps) and a body: the instructions the model follows — what to run, how to relay, when to ask. The registry assigns each skill a contract class; a mechanical stamper writes the class’s canonical contract text into every body, and check (463 validations) fails the build on drift, missing entries, orphan folders, or bodies over the token ceiling (warn 500 · fail 800). Authoring a new skill = one folder + one registry line; the governance arrives by stamping, not by remembering.

02 · Demand paging

Why 97 skills cost 42 tokens

Only three conversational skills (help, nextsteps, status) sit in the session index — ~14 tokens each, ≈42 tokens total, the entire fixed cost of a session. The other 94 are slash-only: their bodies load when a human invokes them, cost once, and are cached for the session. Cost scales with governed work, never with logins. Large command outputs return a bounded preview plus a hash-bound handle instead of flooding the transcript (sflow show expands on request), keeping the context append-only and cache-valid.

03 · One invocation, end to end

The invocation loop

you        /sflow-status PAY-1187
host       loads sflow-status/SKILL.md into context (first use this session)
model      follows the body → emits a tool call: singularity-flow status PAY-1187
kernel     child process · resolves subject · reads state · zero tokens
result     envelope: output + why[] + next[] (+ preview/handle if large)
model      relays under its contract (concise-relay: the preview, verbatim,
           no invention) and surfaces the NOW/THEN actions

The model never computes state and never executes — it requests, the kernel executes, the model narrates. Every invocation also emits a structured conformance event (output hash, reply hash, receipts consumed, actions executed); pure-function checkers score whether the contract was followed, per skill, per model. Contract-following is a measured rate, not a hope.

04 · The contracts

Six behavioral classes

Class behaviorGuarantee
Relay (status, report, show)Deterministic output relayed faithfully — the preview verbatim, nothing invented, nothing summarized away
Review (inbox, review)Presents packets and evidence; renders decisions to humans, never makes them
Guided (next, run)Executes at most one kernel-computed action per invocation, then stops
Selection-gated mutation (start, approve, submit)A question with a one-time receipt precedes the mutation; the mutation must consume that receipt — order in the transcript proves nothing, receipt consumption proves everything
Clarification + artifact (continue)Unresolved questions are asked before drafting; answers become hash-pinned inputs the artifact must cite
Conversational (help, nextsteps, status)Indexed, tiny, read-only — the only always-present surface
05 · The big loop

/sflow-continue — the five-intent cycle

┌─→ WHERE AM I     kernel: phase, generation, gates (L0, zero tokens)
│   CLARIFY        model asks what pinned inputs don't resolve → answers pinned
│   GENERATE       model drafts from composed, hash-pinned context (the tokens)
│   PUBLISH        kernel: template validation · hash · isolated commit · CAS
│   VERIFY         kernel: gates, floors, reconcile — refusals are to-do lists
└── NEXT           kernel: nextsteps → NOW/THEN → loop, or stop at a human

The kernel owns the loop; the model fills exactly one slot in it (generation) and narrates the rest. The loop stops — loudly, with reasons — at every human boundary: approvals, unanswered questions, gate failures, escalations. A session can die at any arrow: state is on the branch, and the next continue, on any machine, re-enters the loop where truth left it. Mutations along the way ride the action envelope: kernel-computed plans, content-hashed, revision-bound, one action per execution — an invalid call is unexpressible, not caught.

06 · Adding your own

Extending the surface

New skill: create the folder, add the registry line with a class, run the stamper — contract text, token policy, and check coverage arrive mechanically; the tripwire suite demands a registered case if the wrapped operation is model: never. New workflow verbs come from work types (phases in workflow.yml), not new machinery: skills stay thin doors to kernel commands. The invariant every extension inherits: the skill layer can make the kernel easier to ask — it can never make it possible to bypass.
